AvNav OchartsNG
===============
This repo contains a new implementation for the [o-charts](https://o-charts.org/?lng=en) support in [AvNav](https://www.wellenvogel.net/software/avnav/docs/hints/ocharts.html?lang=en).

It is based on the [avnav-ocharts-provider](https://github.com/wellenvogel/avnav-ocharts-provider) and the [OpenCPN](https://github.com/OpenCPN/OpenCPN) and [o-charts_pi](https://github.com/bdbcat/o-charts_pi) code. Especially it uses the display mechanisms and chart encryption handling from [o-charts_pi](https://github.com/bdbcat/o-charts_pi).

The functionality is very similar to the original avnav-ocharts-provider. But this new plugin is also available for android.

Currently the project is in a beta status. 
Documentation is still missing at many points.

------

  * still some optimizations and caches missing


On-device S-57 chart conversion (Android)
-----------------------------------------
The Android app can convert unencrypted S-57 chart sets (e.g. the free NOAA ENC
charts) to senc chart sets directly on the device - no PC and no OpenCPN needed.

Usage:

  1. Download a chart zip (e.g. an ENC region zip from
     https://www.charts.noaa.gov/ENCs/ENCs_indv.shtml) to the device.
     The zip must contain the base cells (.000), any update files
     (.001, .002, ... - they must sit next to their base cell) and the
     text description files (.TXT). A directory that was unpacked from
     an ENC zip with this structure works as well.
  2. In the avocharts app use the "Import S-57" toolbar button, pick the
     zip file with the Android file picker and choose a name for the
     chart set.
  3. A foreground service converts the cells (progress notification with
     a cancel action). When it finishes, the set is scanned and shows up
     in AvNav like any other chart set.

The conversion pipeline is a Java port of the [tools/senc](tools/senc)
python code (sqlite to senc) plus a statically linked ogr2ogr binary
that converts each S-57 cell to an intermediate sqlite database -
executed from the app's native library directory like liboexserverd.so.
The code lives in
[android/app/src/main/java/de/wellenvogel/ochartsprovider/convert](android/app/src/main/java/de/wellenvogel/ochartsprovider/convert).

Note: cells whose update files are applied report edition 0 in the dsid
record. The provider currently marks such charts "ignored", so updated
cells may not be displayed - this matches the output of the desktop
converter (see tools/tosenc.py) but is still under investigation.

Building the ogr2ogr binary
---------------------------
The binary is not committed to git (jniLibs is gitignored). Rebuild it with:

    tools/build-gdal-android.sh            # both arm64-v8a and armeabi-v7a
    tools/build-gdal-android.sh arm64-v8a  # one ABI only

It fetches and builds GDAL 3.13.3 + PROJ 9.9.0 + sqlite3 statically with
a minimal driver set (S57 reader, SQLite/GeoJSON writers), verifies the
result on a connected device if one is found, and installs it as
libOgr2Ogr.so into android/app/src/main/jniLibs/<abi>/.
Requires: Android SDK/NDK, cmake, ninja, python3, curl.

Tests
-----
Host-side unit tests (no device needed):

    cd android
    ./gradlew :app:testDebugUnitTest

They cover the senc writer, WKB reader, geometry handling, the
sqlite-to-senc port (incl. a golden corpus of real NOAA cells compared
record-by-record against output generated by the upstream python
converter) and the import orchestration with a fake ogr2ogr runner.
